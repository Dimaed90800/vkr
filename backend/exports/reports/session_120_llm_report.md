# Итоговый отчёт по результатам автоматизированного тестирования безопасности REST API

## Краткое резюме
В ходе автоматизированного тестирования безопасности REST API для цели "crapi" были выявлены 2 находки, из которых одна является кандидатом на избыточную выдачу свойств объекта (BOPLA). Уровень риска для обнаруженных проблем оценён как средний. Рекомендуется провести ручную верификацию для подтверждения выявленных уязвимостей.

## Основные находки

1. **Находка 1**
   - **Тип:** Возможная BOPLA
   - **Endpoint:** http://host.docker.internal:8888/community/api/v2/community/posts/recent
   - **Уровень критичности:** Средний
   - **Статус верификации:** Подтверждён
   - **Краткое описание:** Ответ на запрос к указанному endpoint раскрывает потенциально чувствительные поля: posts.author.email.
   - **Интерпретация результата:** Обнаружение избыточной выдачи данных может привести к утечке личной информации пользователей, что представляет собой серьёзную угрозу для конфиденциальности.

2. **Находка 2**
   - **Тип:** Диагностический сигнал аутентификационной границы
   - **Endpoint:** http://host.docker.internal:8888/identity/api/v2/user/dashboard
   - **Уровень критичности:** Низкий
   - **Статус верификации:** Подтверждён
   - **Краткое описание:** Известный endpoint с высокой ценностью вернул HTTP 404 во время проверки аутентификационной границы. Это не подтверждённый обход, но является полезным сигналом для ручной проверки экспозиции маршрута, обработки методов и контроля аутентификации.
   - **Интерпретация результата:** Данный сигнал указывает на необходимость дополнительного анализа для выявления возможных уязвимостей в механизмах аутентификации и авторизации.

## Рекомендации по устранению
- Для устранения проблемы с возможной избыточной выдачей свойств объекта (BOPLA) необходимо:
  - Провести аудит и ограничить доступ к чувствительным полям в ответах API, основываясь на ролях пользователей и их правах.
  - Реализовать строгую проверку прав доступа для каждого атрибута, возвращаемого в ответах API.

- Для диагностического сигнала аутентификационной границы:
  - Рекомендуется провести ручной анализ маршрута и методов, чтобы убедиться в правильной настройке аутентификации и авторизации для защищённых ресурсов.

## Итоговая оценка
Автоматизированное тестирование выявило одну подтверждённую уязвимость, связанную с избыточной выдачей данных, и один диагностический сигнал, требующий ручной проверки. Рекомендуется принять меры по устранению выявленных проблем для повышения уровня безопасности API.
