# Итоговый отчёт по результатам автоматизированного тестирования безопасности REST API

## Краткое резюме
В ходе автоматизированного тестирования безопасности REST API для цели "crapi" были выявлены 3 находки, из которых 2 подтверждены, а 1 является кандидатом на дальнейшую верификацию. Обнаружены проблемы, связанные с объектным разграничением доступа и избыточным раскрытием данных.

## Основные находки

1. **Тип:** Возможное нарушение уровня свойств объекта (BOPLA)  
   **Endpoint:** http://host.docker.internal:8888/community/api/v2/community/posts/recent  
   **Уровень критичности:** Средний  
   **Статус верификации:** Подтверждено  
   **Краткое описание:** Ответ на запрос к указанному endpoint раскрывает потенциально чувствительные поля: posts.author.email.  
   **Интерпретация результата:** Обнаружение избыточного раскрытия данных может привести к утечке личной информации пользователей, что создает риски для конфиденциальности.

2. **Тип:** Диагностический сигнал границы аутентификации  
   **Endpoint:** http://host.docker.internal:8888/identity/api/v2/user/dashboard  
   **Уровень критичности:** Низкий  
   **Статус верификации:** Подтверждено  
   **Краткое описание:** Известный высокоценный endpoint вернул HTTP 404 во время проверки границы аутентификации. Это не подтверждённый обход, но является полезным сигналом для ручной проверки маршрута, обработки методов и контроля аутентификации.  
   **Интерпретация результата:** Необходима ручная проверка для оценки безопасности данного endpoint и его обработки запросов.

3. **Тип:** Возможное нарушение уровня объекта (BOLA)  
   **Endpoint:** http://host.docker.internal:8888/identity/api/v2/vehicle/4bae9968-ec7f-4de3-a3a0-ba1b2ab5e5e5/location  
   **Уровень критичности:** Высокий  
   **Статус верификации:** Кандидат  
   **Краткое описание:** Один и тот же endpoint был доступен для ролей user_a и user_b с успешными ответами и эквивалентными объектами.  
   **Интерпретация результата:** Необходима ручная верификация для проверки прав доступа и контекста бизнеса, так как это может указывать на уязвимость в разграничении доступа.

## Рекомендации по устранению
1. **Для BOPLA:** Необходимо провести аудит ответов API и ограничить доступ к чувствительным полям, таким как email авторов постов. Рассмотреть возможность применения механизма фильтрации данных в ответах API.
   
2. **Для диагностического сигнала:** Рекомендуется провести ручную проверку endpoint, который вернул HTTP 404, для оценки его безопасности и корректности обработки аутентификации.

3. **Для BOLA:** Рекомендуется провести ручную верификацию прав доступа для ролей user_a и user_b к указанному endpoint, чтобы убедиться в корректности разграничения доступа и предотвратить возможные уязвимости.

## Итоговая оценка
Автоматизированное тестирование выявило несколько значительных проблем, требующих внимания. Подтверждённые находки указывают на потенциальные риски, связанные с безопасностью данных и доступом к объектам. Рекомендуется провести ручную верификацию для кандидатов на уязвимости и принять меры по устранению выявленных проблем.
