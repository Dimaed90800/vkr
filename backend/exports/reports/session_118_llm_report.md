# Итоговый отчёт по результатам тестирования безопасности REST API

## Краткое резюме
В ходе автоматизированного тестирования безопасности REST API для цели "crapi" были выявлены 2 находки, из которых одна является кандидатом на избыточную выдачу свойств объекта (BOPLA). Уровень риска для обнаруженных проблем оценён как средний. Рекомендуется провести ручную верификацию для подтверждения выявленных уязвимостей и анализа бизнес-необходимости.

## Основные находки

1. **Находка 1**
   - **Тип:** Возможная BOPLA
   - **Endpoint:** http://host.docker.internal:8888/community/api/v2/community/posts/recent
   - **Уровень критичности:** Средний
   - **Статус верификации:** Подтверждён
   - **Краткое описание:** Ответ на запрос к указанному endpoint раскрывает потенциально чувствительные поля: posts.author.email.
   - **Интерпретация результата:** Обнаружение избыточной информации может привести к утечке личных данных пользователей, что создаёт риски для конфиденциальности и безопасности.

2. **Находка 2**
   - **Тип:** Диагностический сигнал аутентификационной границы
   - **Endpoint:** http://host.docker.internal:8888/identity/api/v2/user/dashboard
   - **Уровень критичности:** Низкий
   - **Статус верификации:** Подтверждён
   - **Краткое описание:** Известный endpoint с высокой ценностью вернул HTTP 404 во время проверки аутентификационной границы. Это не подтверждённый обход, но является полезным сигналом для ручного анализа маршрута, обработки методов и контроля аутентификации.
   - **Интерпретация результата:** Необходима ручная проверка для оценки возможных уязвимостей в аутентификации и доступности данного endpoint.

## Рекомендации по устранению
1. **Для находки 1 (BOPLA):**
   - Провести аудит и ограничить доступ к чувствительным полям в ответах API, чтобы предотвратить избыточную выдачу данных.
   - Реализовать строгую проверку прав доступа для каждого атрибута, возвращаемого в ответах API.

2. **Для находки 2 (диагностический сигнал):**
   - Провести ручной анализ маршрута и методов, связанных с endpoint, чтобы убедиться в корректной настройке аутентификации и авторизации.
   - Рассмотреть возможность улучшения обработки ошибок для предотвращения утечек информации о структуре API.

## Итоговая оценка
Автоматизированное тестирование выявило одну подтверждённую уязвимость, связанную с избыточной выдачей данных, и один диагностический сигнал, требующий ручной проверки. Рекомендуется принять меры по устранению выявленных проблем и провести дополнительный аудит безопасности для повышения уровня защиты API.
